# Стенд esp32sim — проверка прошивки без платы

Стенд гоняет настоящий образ прошивки станции в эмуляторе ESP32-S3
(`/srv/kouki-workspace/_scratch/esp32sim`, исходники — отдельный проект вне
репозитория; доска `waveshare-lcd185c` — та же, что на плате) и сам решает,
прошёл сценарий или нет. Один прогон даёт три артефакта: лог консоли, снимок
экрана и запись звука.

Зачем: правки FSM, wake-word, UI и сети видно быстро и без платы — за секунды
(один сценарий целиком, см. замеры в разделе про `--realtime`), включая то, что
на плате ловится глазами (пустой экран, тишина вместо озвучки, падение
в `Guru Meditation`). Плата остаётся финальной проверкой: эмулятор не
воспроизводит реальный аналог микрофона (см. «Известные ограничения»).

## Сборка sim-образа

Образ для стенда отличается от боевого двумя вещами, и обе включаются флагами
`tools/build-linux.sh`, каждый — отдельным файлом defaults:

| флаг | файл | что даёт |
| --- | --- | --- |
| `--sim` | `sim/sdkconfig.sim.defaults` | `CONFIG_KOUKI_TEST_CONSOLE_CMDS=y` — тестовые команды консоли (`test_seed_history`, `test_mock_done`) |
| `--sim-mic` | `sim/sdkconfig.sim-mic.defaults` | `CONFIG_KOUKI_SIM_MIC=y` — микрофон из `i2s_wav` вместо ES7210, нужен сценариям с голосом |

Сборка под весь набор сценариев — оба флага сразу:

```bash
bash tools/build-linux.sh --sim --sim-mic --build-dir /srv/kouki-workspace/_scratch/build-kouki-station-sim
```

Флаги складываются: каждый дописывает свой файл к `sdkconfig.defaults`
в порядке указания (более поздний файл побеждает), в строке `Defaults:` видны
все. `--extra-defaults FILE` работает так же и тоже складывается с ними.

Сборка **без** `--sim-mic` — это «стенд без sim-микрофона»: сценарии `boot`,
`ui-touch`, `network-roundtrip` на ней проходят, а голосовые (`wake`,
`wake-false-positive`, `followup`) падают с `в логе нет «распознано «эй гин»»`
и запрещённым `read_mic(56): чтение микрофона не удалось`. Так и должно быть:
молчаливый PASS тут означал бы, что стенд врёт.

Каталог сборки держите отдельным от боевого: `build-linux.sh` сверяет
`sdkconfig` с defaults (включая оба флага стенда) и сам пересоздаёт его при
расхождении — но смешивать sim- и боевую сборку в одном каталоге не нужно.

Секретов в sim-образе нет: Wi-Fi, адрес и токен сервера стенд кладёт в NVS-образ
(раздел ниже).

## Запуск

Один сценарий:

```bash
bash tools/sim-run.sh --build /srv/kouki-workspace/_scratch/build-kouki-station-sim --scenario boot
```

Все сценарии подряд со сводным вердиктом:

```bash
bash tools/sim-run.sh --build /srv/kouki-workspace/_scratch/build-kouki-station-sim --all
```

Артефакты по умолчанию — `_scratch/sim/<YYYYMMDD-HHMMSS>-<сценарий>/`
(для `--all` — `<ts>-all/<сценарий>/`), внутри:

| файл | что это |
| --- | --- |
| `run.log` | весь вывод эмулятора (консоль прошивки + сообщения esp32sim) |
| `screen.png` | снимок TFT 360×360 на момент завершения сценария |
| `out.wav` | захват I2S-выхода (озвучка ответа, сигналы) |
| `verdict.txt` | `PASS` или `FAIL: причина`, дальше по строке на каждое правило |
| `scenario.script` | тело сценария, как его получил эмулятор |

Сколько это занимает настенного времени — таблица замеров в разделе
«`--realtime` и ASR-подтверждение» (числа ориентировочные, зависят от машины
и от скорости ASR).

Коды возврата `sim-run.sh`: `0` — PASS, `1` — FAIL сценария (в том числе
пустой PNG или тишина в WAV), `2` — неверные аргументы, `3` — стенд не готов
(нет эмулятора, ROM, файлов сборки, NVS). Код 3 — это не дефект прошивки, и
путать его с FAIL нельзя. `--all` возвращает 0 только если прошли все сценарии,
и 3, если хотя бы один сценарий не смог стартовать из-за окружения.

Полезные флаги: `--out DIR` (свой каталог артефактов), `--timeout SEC` (предел
настенных секунд на сценарий, по умолчанию 240), `--` — всё после него уходит в
esp32sim как есть (`--scenario boot -- --realtime`).

## Формат `.scenario`

Файл в `sim/scenarios/` состоит из трёх частей.

Заголовок (необязательный), по строке на ключ:

| ключ | смысл |
| --- | --- |
| `max-seconds: N` | сколько эмуляционных секунд гонять (по умолчанию `SIM_MAX_SECONDS=30`) |
| `nvs: имя` | NVS-образ из `sim/nvs/имя.csv` (по умолчанию `net`) |
| `audio: nonsilent` | требовать непустой `out.wav` (пик ≥ 1000) |
| `png-min-bytes: N` | порог «экран отрисовался» (по умолчанию 2000 байт) |
| `esp32sim: <аргументы>` | доп. флаги эмулятора для этого сценария (см. ниже) |

`esp32sim:` нужен затем, что `--` прокидывает аргументы только в один прогон,
а под `--all` у каждого сценария свои требования. Пока используется один флаг:
`esp32sim: --realtime` в `wake-false-positive.scenario`.

### `--realtime` и ASR-подтверждение

`--realtime` — флаг самого esp32sim; он описан в `_scratch/esp32sim/docs/cli.md`
(раздел про запуск), но **в `esp32sim --help` его нет**, так что искать его там
бесполезно. Он гоняет эмулятор в темпе реального времени (по умолчанию —
быстрее) и нужен там, где прошивка ждёт сетевого ответа в жёсткий таймаут:
ASR-подтверждение кодового слова ждёт ответ сервера
`CONFIG_KOUKI_WAKE_VERIFY_TIMEOUT_MS` = 4000 мс по своим часам. Без реального
темпа эмулятор пробегает эти 4 с за доли секунды, Whisper не успевает
ответить, и прошивка уходит в офлайн-ветку «принимаю локальный хит».

Цена — прогон идёт в темпе реального времени. Замер на этом сервере (каждый
сценарий отдельно, машина в простое):

| сценарий | настенное время |
| --- | --- |
| `boot` | ~6 с |
| `wake` | ~9 с |
| `ui-touch` | ~9 с |
| `wake-false-positive` | ~11 с (единственный с `--realtime`) |
| `followup` | ~18 с |
| `network-roundtrip` | ~21 с |
| `--all` (все шесть подряд) | ~1 мин 15 с |

Сумма отдельных прогонов (74 с) и `--all` (74 с) сходятся — то есть
`--all` не добавляет заметного накладного расхода сверх сборки и эмулятора.
Числа ориентировочные, не контракт: они зависят от машины и от того, насколько
быстро отвечает ASR. Если ASR не успел (сервер занят, флага нет), сценарий
честно падает с перечнем недостающих строк про ASR — `FAIL: в логе нет
«ASR-подтверждение:»; в логе нет «ложный хит отменён ASR-проверкой»` — а не
зеленеет на офлайн-ветке: `- ASR-проверка недоступна — принимаю локальный хит`
в expect стоит именно запретом, чтобы «повезло/не повезло» не превращалось
в «то PASS, то FAIL».

Тело — action-скрипт esp32sim (`<секунды> <команда> [аргументы]`), формат
описан в `_scratch/esp32sim/docs/cli.md`. Частые команды: `serial <текст>` —
строка в USB-консоль прошивки, `touch X Y 1|0` — касание, `press btn1 150` —
кнопка, `i2s_wav 1 mic.wav` — подать WAV в I2S RX, `stop` — конец прогона.
Пустые строки и строки с `#` игнорируются.

Блок `expect:` — правила проверки, по строке на правило:

- `+ шаблон` — `grep -F` обязан найти шаблон в `run.log`;
- `- шаблон` — обязан НЕ найтись (паника, `abort()`, `assert failed`).

Шаблон ищется как фиксированная строка, регулярки не нужны. Каждое правило
попадает в `verdict.txt` отдельной строкой `ok`/`FAIL`, поэтому разбор упавшего
сценария не требует чтения всего лога.

## Сценарии

| сценарий | образ | что проверяет |
| --- | --- | --- |
| `boot` | `--sim` | консоль, DHCP, конфигурация сервера, стартовое состояние FSM `IDLE` |
| `ui-touch` | `--sim` | переход на экран настроек касанием, тумблер wake-word, слайдер громкости |
| `network-roundtrip` | `--sim` | тестовые команды консоли → `DONE` → озвучка ответа (WAV не тишина) |
| `wake` | `--sim --sim-mic` | кодовое слово «эй гин» из `i2s_wav` → хит детектора → `IDLE -> RECORDING` |
| `wake-false-positive` | `--sim --sim-mic` | посторонняя речь дала ложный хит → ASR его отменил → `RECORDING -> IDLE`, без SENDING; идёт под `--realtime` |
| `followup` | `--sim --sim-mic` | окно продолжения: `DONE -> FOLLOWUP` → речь в окне без кодового слова → `FOLLOWUP -> RECORDING` |

Колонка «образ» — минимум, на котором сценарий осмыслен: голосовым нужен
`KOUKI_SIM_MIC` (то есть сборка с `--sim-mic`), остальным — только тестовые
команды консоли. `--all` гоняет все шесть, поэтому зелёный `--all` бывает
только на сборке с обоими флагами.

`wake-false-positive` понижает порог детектора до минимума (`serial
set_wake_th 10`): на штатных 65 % посторонняя речь не даёт хита вовсе, и
проверять отмену было бы не на чем. Это осознанная настройка сценария, а не
дефект — в самом файле сценария она прокомментирована.

## NVS-образ: Wi-Fi и сервер

Прошивка берёт настройки из NVS (`namespace kouki_config`), а не из образа.
Шаблон лежит в `sim/nvs/<имя>.csv`, стенд сам генерирует из него бинарь
утилитой `nvs_partition_gen.py` из ESP-IDF при каждом прогоне — руками это
бывает нужно редко. Команда ниже — целиком на абсолютных путях, поэтому
работает из любого каталога:

```bash
/srv/kouki-workspace/_scratch/esp-tools/python_env/idf5.5_py3.14_env/bin/python \
  /srv/kouki-workspace/_scratch/esp-idf/components/nvs_flash/nvs_partition_generator/nvs_partition_gen.py \
  generate /srv/kouki-workspace/_scratch/wt/kouki-station-t120-sim/sim/nvs/net.csv \
  /srv/kouki-workspace/_scratch/sim/nvs/net.bin 0x6000
```

Генератор при ошибке (нет CSV, нет такого каталога) печатает traceback и
оставляет пустой файл-назначение. Стенд это переживает: `sim-run.sh` считает
NVS-образ негодным, если он меньше сектора или его размер не кратен 4096,
и генерирует заново (`NVS: образ … негодный (0 байт…) — пересоздаю`). Если
генератор недоступен, прогон заканчивается кодом 3 с сообщением про NVS, а не
FAIL-ом сценария.

Адрес и токен сервера в CSV — демо-значения; реальные подставляются из
окружения при каждом прогоне:

```bash
SIM_SERVER_URL=http://192.168.1.50:5300 SIM_SERVER_TOKEN=мой-токен \
  bash tools/sim-run.sh --build ... --scenario boot
```

Подставленный CSV пишется в `_scratch/sim/nvs/`, в git остаётся только
демо-шаблон; токен в лог не печатается. Другие переменные окружения (значения
по умолчанию — в `tools/sim-env.sh`): `SIM_BIN`, `SIM_ROM`, `SIM_BOARD`,
`SIM_BUILD`, `SIM_NET`, `SIM_OUT_ROOT`, `KOUKI_SIM_NVS`, `SIM_SCENARIOS`
(каталог сценариев для `--all`, удобно гонять временную копию).

## Известные ограничения

- **Микрофон: 4 канала на плате против 1–2 слотов в эмуляторе.** Станция читает
  ES7210 по TDM, 4 канала (`bsp_get_feed_data()` перекладывает их в «RMNM»);
  эмулятор I2S RX умеет только моно/стерео и не умеет TDM. Поэтому реальный
  микрофонный путь в эмуляторе не воспроизводится, и звук подаётся через
  `i2s_wav` в отдельном режиме `KOUKI_SIM_MIC` (только sim-сборка, по умолчанию
  выключен; поведение платы он не меняет).
- **Wake-word глушится 2500 мс после старта** (`kouki_wake_mute(2500)`): подавать
  кодовое слово раньше этого срока бессмысленно.
- **Для wake нужна живая запись, а не тон.** Детектор обучен на речи: синусоида
  и шум не срабатывают. Фикстуры — `sim/fixtures/mic/*.wav`, 16 кГц моно PCM16,
  до 100 КБ.
- **LVGL-свайп в эмуляторе ограничен двумя точками касания.** Перетаскивание
  слайдера работает, а «инерционный» свайп по плиткам — нет; на нужную плитку
  попадаем последовательностью тачей (см. `ui-touch.scenario`).
- **Время в логе эмуляционное.** Тайминги сценария отсчитываются от эмуляционных
  секунд, и прогон идёт быстрее реального времени — кроме сценариев
  с `esp32sim: --realtime`, которые идут в темпе реального времени.
- **На реальном железе звук и микрофон не проверяются этим стендом.** Финальная
  проверка — прошивка на плату (`tools/flash-linux.sh`) и живой диалог.
