# Модель угроз и секреты

Документ отвечает на два вопроса: от кого станция защищена, и что будет, если плата
попадёт в чужие руки. Он же — список того, что осознанно **не** защищено, чтобы не
было иллюзий.

## Что защищаем

| Актив | Где живёт | Цена утечки |
| --- | --- | --- |
| Bearer-токен API | `firmware/sdkconfig.secret`, дальше — образ | Чужой может слать запросы на сервер от имени станции: создавать задачи, читать список, подсовывать вопрос в разбор |
| Пароль Wi-Fi | там же | Доступ в домашнюю сеть (в зависимости от того, что ещё в ней есть) |
| Записи речи | `Kouki:**AudioDirectory`, 30 дней (`AudioRetentionDays`) | Обрывки личной речи |
| Задачи и журнал распознавания | `kouki.sqlite` на сервере | Содержание дел |
| Сервер | `Kagedama.api` | Все данные выше разом |

## Кто противник

1. **Тот, у кого есть плата** (нашли, украли, одолжили). Физический доступ = чтение flash,
   если не включены шифрование flash и secure boot. Значит токен и пароль Wi-Fi для него
   не секрет, и вопрос не «как спрятать», а «насколько дорого стоит их сменить».
2. **Сосед по сети / слушатель Wi-Fi** — видит незашифрованный HTTP целиком.
3. **Случайный человек в интернете**, если сервер случайно вынесен наружу: token закрывает
   API, но брутфорс токена и DoS остаются возможными.

Внутренний злоумышленник, вредоносное ПО на сервере и атаки по побочным каналам в модели
не рассматриваются: для домашней станции это не тот класс задач.

## Что уже сделано

- **Токен обязателен на сервере.** Пустой `Kouki:Token` закрывает API; открытый доступ
  включается только явным `Kouki:AllowAnonymous` для локальной отладки. Отказ — 401 и
  `WWW-Authenticate`, отказы логируются с ограничением частоты.
- **HTTPS поддержан на станции.** `esp_http_client` собран с встроенным набором корневых
  сертификатов (`CONFIG_MBEDTLS_CERTIFICATE_BUNDLE=y`): достаточно поставить `https://`
  в `KOUKI_SERVER_URL`, свой CA не нужен.
- **Ошибки различимы.** Станция показывает «Сервер недоступен» (сеть/адрес) и
  «Сервер ответил HTTP 503» (сервер жив, но, например, собран без распознавания) —
  это разные диагнозы, и лечатся они по-разному.
- **Аудио живёт ограниченное время** и удаляется фоновой задачей; размеченные записи
  удаляются вместе с меткой.
- **Разметка и метаданные — в журнале**, а не в логах процесса: журнал `actions` отвечает
  на вопрос «что именно произошло» без разбирания stdout.

## Что осознанно не защищено

| Риск | Почему так | Что делать |
| --- | --- | --- |
| Пароль Wi-Fi и токен лежат в образе | Плата без файловой системы и без UI ввода — иначе нужен отдельный сценарий провижининга | Считать, что при физическом доступе они известны: **токен на устройство**, быстрая ротация |
| Прошивка не подписана | Secure boot на ESP32-S3 включается необратимо и требует своего ключа | Для домашнего использования достаточно записать, кем и когда прошита плата (см. `docs/build.md`) |
| HTTP по умолчанию | В своей сети удобнее и быстрее | Вне своей сети — только `https://` (уже поддержано) |
| Нет ограничения частоты запросов | Один клиент на станцию | Если сервер виден в интернете — ставить reverse proxy с rate limit |

## Требования к эксплуатации

1. **Свой токен на каждую станцию** (`KOUKI_SERVER_TOKEN`), не общий на всех: тогда
   компрометация одной платы не открывает остальные.
2. **Смена токена — процедура, а не авария**: поменять `Kouki__Token` на сервере,
   `CONFIG_KOUKI_SERVER_TOKEN` в `firmware/sdkconfig.secret`, пересобрать, прошить.
3. **`firmware/sdkconfig.secret` не коммитится** (он в `.gitignore`) и создаётся
   из шаблона на машине сборки; в переписке и CI используются переменные окружения.
4. **Wi-Fi станции — отдельная сеть или VLAN**, если в домашней сети есть чужие устройства.
5. **Сервер не выносится в интернет** без обратного прокси с TLS и ограничением частоты.
6. При подозрении на кражу платы: сменить токен, проверить журнал `actions` за период,
   удалить неразобранные записи, при необходимости — перепрошить.

## План на будущее (задачи)

- **Провижининг секретов в NVS** вместо констант образа (одна прошивка на все платы,
  токен заливается при настройке) — задача T46.
- Шифрование flash и secure boot — обсудить, когда станций станет больше одной.
- Ограничение частоты на `/api/voice` и `/api/intake` — если сервер вообще поедет наружу.
